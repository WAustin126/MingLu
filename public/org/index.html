第 1 步：导入要检查的表单

把要检查的表单放进来：示例、文件、拍照都可以。系统会先把表单读成一份内容清单——每一项填什么、是不是必填，都列清楚。没有这份清单，就不往下修，免得漏掉。

导入方式

纸质表拍照、PDF 电子表、Word 文档都可以，AI 会把里面的填写项读出来。下一步会按读出的结构逐项检查这张表自己（标题、必填、类型、分组、说明），修好后发布的就是这张表。导入成功后自动进入下一步。

高级方式（粘贴代码 / 导入千问办公的处理结果）

在千问办公别处跑完的 form.schema.json + issues.json，可直接拿回来用，不必重跑全流程。导入认不认，看页面显示的文件名和字段数。

      修好的表单和报告（每件都能复查）

      产物用途怎么复查
      issues.json问题清单：每条问题、等级、定位与证据逐条对照本页报告与原表行号
      form.schema.json内容清单：每一项、类型、必填、顺序、分组项数可与第 1 步的内容清单核对
      fixed.html修复版表单：可预览、可下载、可发布到个人端用同一扫描器复扫验证

      边界（主动写明，不冒充全能）

      • 只检结构与格式：标签关联、必填标识、报错说明、字段完整性；不判业务内容真假。
      • 不收集真实个人信息：不收集、不保存；演示与测试数据全部虚构。
      • 拿不准不硬判：无法确定的项标成「需要你拍板」，由机构人员逐项决定，不自动修复。
      • 极端异形表单：结构太特殊时进「需要你拍板」，或建议走线下窗口，不硬检、不硬修。
      • 修复可回退：修复生成新文件、原表不动；不满意可回退重来。
      • 数字口径：示例表的「13 类 / 16 处」为 a11y_scan.py 对 original.html 的扫描结果，修复后 0 类 / 0 处为同一扫描器复扫；导入的表单由浏览器按结构规则现场扫描与复扫，数字以本页报告为准，仅适用于当前这张表。
